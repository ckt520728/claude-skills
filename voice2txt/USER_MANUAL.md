# Voice2Txt 使用者手冊

版本：2026-11-13（Windows 桌面版）

Voice2Txt 把你說的話即時轉成文字，有三種模式：

| 模式 | 你說 | 畫面輸出 |
| --- | --- | --- |
| 繁體中文 | 中文 | 繁體中文（台灣用語） |
| English | 英文 | 英文 |
| 中文 → English | 中文 | 英文譯文（並另外顯示中文原文供核對） |
| 隨便問 | 一個問題或指令 | LLM 的回答（見「隨便問」一節；需要 LLM） |

### 設計原理：兩階段處理

```
第一階段  Whisper 語音轉文字（本機）  ──▶  原始轉錄：「嗯，那個，我們明天下午三點，不對，是四點開會」
第二階段  LLM 整理與去雜訊            ──▶  整理結果：「我們明天下午四點開會。」
          （中翻英模式同時翻譯）       ──▶  “We have a meeting tomorrow at 4 p.m.”
```

- **Whisper 負責「聽」**：把聲音忠實轉成文字，連贅詞、重複、口誤都一起轉出。
- **LLM 負責「整理」**：去除贅詞（嗯、呃、那個、um、uh）與重複字詞；說話者明確更正時（「不對」「我是說」「sorry, I mean」），只保留更正後的內容；依上下文修正錯字、補上標點；中翻英模式同時翻成英文。
- **不增刪資訊**：LLM 被要求保留所有事件、否定、日期、時間、地點、數量與名稱。「禮拜一，不是禮拜二」屬於資訊，會完整保留，不會被當成口誤。
- **原始轉錄一定保留**：畫面下方「Whisper 原始轉錄」區與歷史紀錄都會保存整理前的文字，方便核對 LLM 有沒有改錯。

測試中，同樣含贅詞與口誤的 5 段語音，**僅 Whisper 5 段都未通過**，加上本機 LLM 整理後 5 段都通過（見第 10 節）。

語音辨識在你的電腦上完成，不需要訂閱或帳號。預設的 LLM 也在你的電腦上執行（Ollama）；只有在你自行設定雲端備援時，才會把 Whisper 轉錄的**文字**送到 Anthropic、OpenAI 或 Google。

## 1. 系統需求

| 項目 | 需求 |
| --- | --- |
| 作業系統 | Windows 10／11 64 位元 |
| 麥克風 | 任一 Windows 可辨識的麥克風或耳機麥克風 |
| 磁碟空間 | 一般版約 1 GB；GPU 版約 7.8 GB |
| 顯示卡（選用） | NVIDIA 顯示卡可使用 `medium`／`large-v3` 模型，速度快很多 |
| 本機 LLM（選用，中翻英建議） | [Ollama](https://ollama.com) 與本機模型，預設 `gemma4`（約 9.6 GB） |

## 2. 安裝與啟動

1. 取得整個 `Voice2Txt` 資料夾（內含 `Voice2Txt.exe` 與 `_internal`）。**請整個資料夾一起複製或移動**，只複製 exe 無法執行。
2. 雙擊 `Voice2Txt.exe`；若從專案資料夾執行，也可雙擊 `啟動桌面版.cmd`。
3. 本程式沒有數位簽章，Windows 可能出現 SmartScreen 藍色視窗。確認來源可信後，按「其他資訊」→「仍要執行」。

## 3. 第一次設定

開啟後切到 **「字典與設定」** 分頁：

1. **Whisper 模型**：決定辨識品質與速度。
   - `small`：一般電腦建議。
   - `medium`／`large-v3`：需要 NVIDIA 顯示卡（運算裝置選 `cuda`）。
   - `base`：最省資源，品質較低。
2. **運算裝置**：`cpu` 任何電腦都能用；`cuda` 需 NVIDIA 顯示卡與 GPU 版程式。
3. **文字處理**：
   - `Whisper + LLM 整理`：**偵測到 Ollama 時自動成為預設**。三種模式都會經過 LLM 整理，中翻英品質也最好（見第 5 節）。選此項時 Whisper 固定用 CPU，建議 `small`。
   - `僅 Whisper`：不需其他軟體，速度最快，但保留所有贅詞與口誤，中翻英也較常漏譯。
4. **麥克風**：選擇要使用的麥克風；`系統預設` 會跟隨 Windows 設定。
5. **個人字典**（選用）：見第 7 節。
6. **外觀**：可選 `系統`（跟隨 Windows 的淺色／深色）、`淺色` 或 `深色`，選了立刻套用到整個視窗（含洞察的方格圖），並記住這個選擇。
7. 按 **「儲存設定與字典」**，再按 **「載入 / 下載模型」**。畫面底部狀態列會顯示目前使用的模型與翻譯順序，例如：
   `small / cpu 已就緒；Whisper 轉錄 → Ollama gemma4:latest → Anthropic claude-sonnet-5-5 (low) → OpenAI gpt-6-luna (high) → Gemini gemini-3.8-flash (low) → Whisper 結果。`（沒有 API key 的雲端服務不會出現在順序裡）

程式內已附模型，載入不需下載。若選了未附的模型，第一次會從網路下載，可能需要數分鐘。

## 4. 開始使用

1. 回到 **「即時語音」** 分頁，在左上方選擇模式。
2. 按 **「● 開始錄音」**，然後自然說話。
3. 說話停頓約半秒，就會輸出一段文字；連續說話時最長每 8 秒輸出一段。
4. 按 **「■ 停止錄音」**。按鈕會顯示「處理尾段…」，等它恢復，最後一句才會完整出現。
5. 文字可直接在畫面上修改，接著可以：
   - **複製全文**：複製到剪貼簿。
   - **匯出 TXT**：存成 UTF-8 文字檔。
   - **清空畫面**：只清除畫面，歷史紀錄仍保留。

### 快捷鍵（在其他程式中使用）

模型載入後，在任何程式中都可以用全域快捷鍵錄音，不必切回 Voice2Txt。預設值：

| 動作 | 預設快捷鍵 | 行為 |
| --- | --- | --- |
| 口述 | `Right Alt`（右邊的 Alt 鍵） | 依「口述語言」設定輸出繁體中文或 English；也保留舊的 `Alt + Shift + Space` |
| 翻譯 | `Right Alt + Right Shift` | 固定使用「中文 → English」 |
| 隨便問 | `Right Alt + Right Ctrl` | 把你說的問題或指令交給 LLM，見下方「隨便問」 |

兩種按法：

- **按住說話**：按住快捷鍵超過 0.35 秒再放開，放開時就停止錄音。
- **短按切換**：按住不到 0.35 秒就放開，視為一次短按，錄音會持續進行；之後再短按一下才停止。用哪一組快捷鍵開始，就只有那一組的短按能停止；若是用「開始錄音」按鈕開始的，任何已設定的快捷鍵短按都能停止。
- `Right Alt` 與 `Right Alt + Right Shift` 共用同一個鍵：按下 `Right Alt` 後會先等約 0.15 秒，確認你沒有接著按 `Right Shift`，才開始口述；因此口述會晚一點點開始，但不會誤判成翻譯。
- 舊的 `Alt + Shift + Space` 仍可使用，行為與其他組合相同：按住 0.35 秒以上放開即停止，短按則切換（短按開始錄音，再短按一下停止）。

**自訂快捷鍵**（「字典與設定」分頁的「快捷鍵」區）：

1. 每個動作（口述、翻譯、隨便問）最多可有兩組快捷鍵。按「設定」會取代該動作原有的組合；按「再加一個」則新增第二組；按「清除」移除。
2. 按下「設定」或「再加一個」後，畫面會顯示「請按下組合鍵…」。依序按下想要的組合鍵（例如 `Right Ctrl + F9`），**全部放開時**就會確認；擷取中按「取消」可放棄。可使用左右 Alt／Shift／Ctrl、Space、Caps Lock、F1–F12、字母與數字等。
3. 按「儲存設定與字典」才會保存；要先載入模型，快捷鍵才會開始錄音。
4. 「口述語言」下拉選單決定口述快捷鍵輸出哪種語言；翻譯快捷鍵固定是中文 → English。

**行為細節**：

- **只隱藏必要的按鍵**：Voice2Txt 絕不攔截任何修飾鍵（Alt、Ctrl、Shift），所以使用 AltGr 的鍵盤配置（例如部分歐洲語系）仍可正常輸入。唯一的例外：當你按下的「非修飾鍵」正好完成一組已設定、且含 Alt 的組合（例如把隨便問設成 `Alt + Space`，按下 Space 的那一刻），這個鍵不會送給前景視窗，否則 Windows 會打開該視窗的系統選單；其他按鍵一律照常送出。若其他程式（如 Typeless）自己攔截了某個鍵，Voice2Txt 也會收不到。
- **不啟動功能表**：Windows 在你單獨按一下 Alt 再放開時，會啟動視窗的功能表列（按 Alt 後畫面上方的選單被反白）。為避免你按 `Right Alt` 口述時，其他程式的功能表被誤開，Voice2Txt 會在放開前插入一個「無作用」的虛擬按鍵（VK 0xFF），讓 Windows 不再把這次按壓當成「單獨按 Alt」。這個機制在正常按鍵速度下有效（稽核以 10–80 毫秒的快速短按測試 38 次，沒有任何一次啟動功能表），但屬於**盡力而為**（以上數字量測於 audit-C（T07 版本），之後的修改尚未重測）：用軟體瞬間（0 毫秒）送出的模擬按鍵測試 8 次，有 3 次仍啟動了功能表。
- **Typeless 衝突**：如果電腦上正在執行 Typeless，它會攔截 `Right Alt`，Voice2Txt 會在狀態列與快捷鍵說明列顯示警告：「偵測到 Typeless 正在執行，Right Alt 會被它攔截；請改設其他快捷鍵或關閉 Typeless。」請照警告改設不含 `Right Alt` 的組合（例如 `Right Ctrl + F9`），或先關閉 Typeless。
- **貼回會等放開**：勾選「完成後貼入原視窗」時，如果快捷鍵還按著（例如按住說話尚未放開），文字會先暫存，**等所有快捷鍵都放開後**才貼出，避免貼上時被按住的 Alt／Shift 干擾成別的快捷鍵。同一個視窗連續產生的多段文字會合併成**一次**貼上（段與段之間以換行相接）。
- 為避免貼錯地方，**只有原視窗仍在最前面時才會貼上**；切換過視窗就會略過，文字仍保留在 Voice2Txt。貼上時會暫用系統剪貼簿，貼完後還原（見下方「快捷鍵錄音後自動貼回與剪貼簿還原」）。
- 若狀態列顯示「無法安裝全域快捷鍵」，請改用錄音按鈕，或關閉占用鍵盤的程式。

### 系統匣、浮動指示器與登入自動啟動

- **關閉視窗縮到系統匣**：預設按視窗右上角的 X 不會結束程式，而是把視窗收到工作列右下角的系統匣（通知區域），快捷鍵繼續有效。在「字典與設定」取消勾選「關閉視窗時縮到系統匣」，X 就會像一般程式一樣結束。
- **系統匣選單**：對系統匣圖示按右鍵，選單有三項：
  - `開啟視窗`：把主視窗叫回來（單擊圖示也可以）。
  - `開始・停止錄音`：切換錄音，效果等同「開始錄音」按鈕。
  - `結束`：真正結束程式（要完全關閉請用這一項）。
- **浮動指示器**：錄音時，螢幕下方中央會出現一個小膠囊，顯示「● 錄音中」與目前的模式；停止後顯示「整理中…」，處理完畢自動消失。它不會搶走焦點，所以你正在輸入的程式不會被打斷。
- **`--minimized`**：用 `Voice2Txt.exe --minimized` 啟動時，不顯示主視窗，只在系統匣常駐；之後按快捷鍵或點系統匣圖示即可使用。
- **登入 Windows 時自動啟動**：在「字典與設定」勾選「登入 Windows 時自動啟動（縮在系統匣）」，程式會在 Windows 目前使用者的啟動項目（登錄 `HKCU\Software\Microsoft\Windows\CurrentVersion\Run`）加入 `Voice2Txt.exe --minimized`；取消勾選會移除。若移動了整個資料夾，請取消再重新勾選，讓啟動項目指向新位置。
- **只會有一個執行個體**：同一時間只能執行一個 Voice2Txt。再次雙擊 `Voice2Txt.exe` 不會開第二個，而是讓已在執行（或縮在系統匣）的那個把視窗顯示出來，第二次啟動隨即結束。

### 隨便問

隨便問讓你「對著電腦說一個問題或指令」，由 LLM 回答。回答會當成口述結果處理：出現在編輯區、存入歷史紀錄，用快捷鍵啟動時也會貼回原視窗。

- **啟動**：預設快捷鍵 `Right Alt + Right Ctrl`（按法與口述相同：按住說話，或短按切換）；也可在「即時語音」的模式選單選「隨便問」後按錄音鈕。舊版預設的 `Right Alt + Space` 會讓 Windows 打開視窗的系統選單，所以已改掉；設定檔若還是舊預設，載入時會自動遷移成新預設（只遷移一次），你自訂過的組合不會被動到，之後你自己刻意設回 `Right Alt + Space` 也會被保留。
- **傳給 LLM 的內容**：你說的話（Whisper 轉出的文字）、前景視窗的標題與程式名稱，以及前景視窗中**你選取的文字**。選取文字的取得方式：錄音開始前，程式先放開還按著的快捷鍵（包含 Alt），再送出一次 `Ctrl+C` 複製選取內容，等目標程式回應複製後（通常是立即，最多等約 0.9 秒）就把剪貼簿還原；如果目標程式太慢、逾時沒回應，這次不使用選取文字，狀態列會提示，之後目標程式回應時剪貼簿仍會自動還原（監看約 2 秒；這段時間內你自己另外複製了東西，或剪貼簿內容不是由目標程式寫入，則不會動它）。選取文字最多傳前 2000 字。
- **怎麼用選取文字**：你的指令若指的是選取文字（改寫、翻譯、摘要、修正、針對它回答），LLM 會把指令套用到那段文字，只輸出可直接貼上的結果；沒有選取文字時，就直接簡短回答。回答語言跟你說的語言相同（說中文答繁體中文，說英文答英文；辨識語言依「口述語言」設定）。
- **需要 LLM**：隨便問沒有「只用 Whisper」的備援。所有 LLM 都不可用時，狀態列顯示「沒有可用的 LLM，顯示原始轉錄」，編輯區只出現你問的那句轉錄，**不會**貼回別的視窗。
- **剪貼簿含圖片、檔案等非文字內容時**：程式無法無損還原，所以會略過選取文字的擷取（也不會放開按鍵、不送 Ctrl+C），並在狀態列說明；這次隨便問只使用你說的話與視窗資訊。前景視窗是 Voice2Txt 自己時，也不另外複製，改用編輯區中選取的文字。
- **隱私**：選取的文字與視窗標題會送到你設定的 LLM。預設是本機 Ollama，資料不離開你的電腦；如果本機 LLM 失敗而啟用了雲端備援（Anthropic、OpenAI、Gemini），這些內容會傳給該雲端服務（只有文字，不含錄音）。含個資或機密的選取內容，請先取消雲端備援的勾選。
- 隨便問的紀錄在「歷史紀錄」分頁可用「隨便問」篩選，且**不計入**洞察的字數與時間。
- 說明：程式只是複製你選取的文字並讀取視窗標題與程式名稱；沒有讀取其他程式輸入欄位的內容（沒有使用 UI Automation），所以沒有選取文字時，LLM 看不到欄位裡的其他內容。

### 依前景 App 調整格式

設定頁的「依前景 App 調整格式（傳送視窗標題與 App 名稱給 LLM）」**預設開啟**。開啟時，口述與翻譯會把前景視窗的標題與程式名稱（**不含視窗內容，也不含選取文字**）交給 LLM，LLM 依 App 類型調整格式：程式碼編輯器保持純文字、不用 Markdown；信件與文件保留段落；聊天軟體保持簡短。關閉後不傳送這些資訊。使用雲端備援時，視窗標題與程式名稱會一併傳到雲端；標題可能含有檔名或網頁標題，請留意。

### 快捷鍵錄音後自動貼回與剪貼簿還原

- 設定頁的「快捷鍵錄音完成後貼回原視窗」**預設開啟**：用快捷鍵（口述、翻譯、隨便問）錄音，完成後文字會自動貼回原視窗。用錄音按鈕錄音時，仍依「完成後貼入原視窗」核取方塊。
- 安全規則不變：只有原視窗仍在最前面、且快捷鍵已全部放開時才會貼上；多段合併成一次貼上。
- 貼上前程式會先存下剪貼簿的**文字**，貼上後約 0.7 秒還原。只處理純文字：剪貼簿原本是圖片、檔案等非文字內容時，無法還原，貼上的文字會留在剪貼簿，狀態列會說明；貼上後剪貼簿又被其他程式改過時，也不會還原。

### 互動聲音

設定頁的「互動聲音」**預設開啟**：開始錄音、停止錄音與發生錯誤時，各播放一個短提示音（開始較高音、停止較低音、錯誤更低且稍長）。取消勾選就完全不出聲。

### 語音輸入時靜音其他音訊

設定頁的「語音輸入時靜音其他音訊」**預設關閉**。開啟後，錄音開始時會把 Windows 目前的**其他程式**音訊靜音（Voice2Txt 自己與系統提示音不受影響；原本就靜音的程式不會動），錄音結束就還原成原來的狀態。

- 錄音停止、處理速度不足而自動停止、關閉程式或程式正常結束時，都會還原。
- **強制結束程式時無法還原**：如果 Voice2Txt 被工作管理員「結束工作」、`taskkill /F` 或當機結束，來不及還原，那些程式會維持靜音，而且 Windows 會記住每個 App 的靜音狀態（重新開啟那些 App 也一樣）。這時請在 Windows 的「音量混音程式」（右鍵工作列喇叭，開啟音量混音程式）把被靜音的程式取消靜音。

### 洞察分頁

第一個分頁「洞察」顯示你的口述統計，每次切到這個分頁就會重新計算：

| 項目 | 說明 |
| --- | --- |
| 口述字數 | 累計字數；字數 = 中日韓文字（每個字算 1）+ 英文等拉丁字母的單字（每個單字算 1） |
| 節省時間 | 假設你每分鐘能打 40 字：字數 ÷ 40 分鐘，扣掉你實際口述花的時間 |
| 平均口述速度、總口述時間 | 依每段的字數與錄音秒數計算 |
| 活躍天數、目前連續天數、最長連續天數 | 有口述紀錄的天數與連續天數 |

下方的方格圖顯示最近 26 週每天的口述字數，滑鼠移到方格上會顯示日期與字數。統計**不包含**「隨便問」。統計來自歷史紀錄，所以刪除歷史紀錄或縮短保留期間，數字也會跟著變少。「節省時間」只是估算，不是實測。

## 5. LLM 整理與備援機制

選擇 `Whisper + LLM 整理` 時，每一段語音的處理流程如下：

```
語音 ─▶ 第一階段 Whisper 轉出原始轉錄
            │
            ▼  第二階段：依序嘗試，成功就停
        ① 本機 Ollama（預設 gemma4）                逾時 20 秒
            │ 失敗
        ② Anthropic claude-sonnet-5-5，強度 low     逾時 30 秒，需 API key
            │ 失敗
        ③ OpenAI gpt-6-luna，推理強度 high          逾時 30 秒，需 API key
            │ 失敗
        ④ Gemini gemini-3.8-flash，強度 low         逾時 30 秒，需 API key
            │ 全部失敗
            ▼
        ⑤ 只用 Whisper：
           繁體中文／English → 直接使用原始轉錄（未整理）
           中文 → English   → Whisper 直接語音翻譯（離線）
```

- 沒有填 API key（也沒有環境變數）的雲端服務會自動略過；取消勾選也可以停用。
- 某個 LLM 失敗後，會**暫停 60 秒**不再嘗試，避免每一段都要等它逾時；60 秒後自動重試，恢復後就回到 Ollama。
- 狀態列會顯示每段實際使用的引擎，例如 `整理：Anthropic claude-sonnet-5-5 (low)（備援啟用：Ollama gemma4:latest：…）`。看到「備援啟用」代表前面的 LLM 有問題；顯示 `整理：Whisper` 代表該段沒有經過 LLM。
- 即使全部失敗，錄音也不會中斷，原始轉錄會存入歷史紀錄。
- 載入模型時若 Ollama 沒有回應，程式仍會完成載入，並先改用備援。

### 5.1 設定本機 Ollama（建議）

1. 從 <https://ollama.com> 下載並安裝 Ollama。
2. 開啟「命令提示字元」，輸入 `ollama pull gemma4`，等待下載完成（約 9.6 GB）。
3. 確認 Ollama 正在執行（工作列右下角有 Ollama 圖示）。
4. 重新開啟 Voice2Txt。若你從未手動選過文字處理方式，會自動改用 `Whisper + LLM 整理`。也可以在設定頁的「① 本機 Ollama 模型」輸入其他已下載的模型名稱。

Voice2Txt 只連線到本機（`127.0.0.1:11434`），會拒絕名稱含 `cloud` 或指向遠端的 Ollama 模型。

### 5.2 設定雲端備援 LLM（選用）

只在前一個 LLM 失敗時使用，**需要你自己的 API key，並依用量付費**。這不是訂閱，但會產生費用；這些模型目前沒有免費額度。可以全部設定、只設定其中一個，或都不設定。

| 順序 | 服務 | 預設模型 ID | 預設推理強度 | 申請 API key |
| --- | --- | --- | --- | --- |
| ② | Anthropic（Claude） | `claude-sonnet-5-5` | `low` | <https://console.anthropic.com> |
| ③ | OpenAI | `gpt-6-luna`（GPT Luna） | `high` | <https://platform.openai.com/api-keys> |
| ④ | Gemini | `gemini-3.8-flash`（Gemini Flash 3.8） | `low` | <https://aistudio.google.com/apikey> |

可自行改的模型 ID：

- **Anthropic**：預設 `claude-sonnet-5-5`；想要更強的模型可輸入 `claude-opus-5-5`（通常較慢、較貴）。推理強度可選 `low`／`medium`／`high`，預設 `low` 以降低每段延遲。
- **OpenAI**：預設 `gpt-6-luna`；也可輸入 `gpt-6.1-terra`。
- **Gemini**：預設 `gemini-3.8-flash`，可自行改（例如 `gemini-4-argon`）。Gemini 預設用 `low`：先前實測 `high` 每段可能超過 30 秒而逾時，而 `low` 的整理品質在測試句中沒有差異。

Anthropic 這一列是 2026-11-13 新增的。程式已有單元測試確認送出的請求格式，但**尚未以真實 Anthropic API key 實際呼叫過**，所以它的整理品質與延遲都還沒有量測數據；第一次使用時請多核對結果。

設定步驟（「字典與設定」分頁）：

1. 在 `② Anthropic 備援`、`③ OpenAI 備援`、`④ Gemini 備援` 三列分別貼上 API key。Anthropic 的 key 到 <https://console.anthropic.com> 的 API Keys 頁面建立。模型 ID 與推理強度已填入預設值，可自行修改。
2. 不想使用某個服務時，取消該列的勾選。
3. 按「儲存設定與字典」，再按「載入 / 下載模型」。
4. API key 會以 Windows DPAPI 加密保存，只有你的 Windows 帳號能解開。也可以不填，改設定環境變數 `ANTHROPIC_API_KEY`、`OPENAI_API_KEY`、`GEMINI_API_KEY`（欄位留空時才會讀環境變數；該列仍需保持勾選）。

**隱私提醒**：使用雲端備援時，該段的 Whisper 轉錄文字會傳到 Anthropic、OpenAI 或 Google；錄音本身不會上傳。內容涉及病患、個資或機密時，請取消三個雲端備援的勾選。

## 6. 歷史紀錄

- **「歷史紀錄」** 分頁會列出每一段結果（時間、模式、前 80 字）。
- 雙擊任一筆即可在「即時語音」分頁查看全文；中翻英的紀錄會一併顯示中文原文。
- 「歷史紀錄」可依「全部／口述／翻譯／隨便問」篩選。
- **保留歷史紀錄**：設定頁的「保留歷史紀錄」可選 `1 週`、`1 個月`、`3 個月` 或 `永久`（預設 `永久`，不會自動刪除）。選了期限後，超過期限的紀錄會在啟動與儲存設定時被**永久刪除**，無法復原。
- **「刪除所有歷史紀錄」** 會永久刪除，無法復原。

## 7. 個人字典

在「字典與設定」輸入常用的專有名詞，用逗號分隔，例如：

```
Voice2Txt, 林口長庚, Alzheimer, 失智症, Gemini
```

字典有兩個用途：提示 Whisper 這些詞可能出現（最多前 1000 字），並在 LLM 整理時作為優先拼法（最多前 500 字），讓 LLM 把聽錯的專有名詞改正。它**不是強制替換**，不保證每次都正確。

### 自動新增（候選）

程式會從「你在 Voice2Txt 即時語音編輯區裡的修改」學習：口述完成後，如果你在編輯區把某個字詞改掉（例如把聽錯的專有名詞改正），當你離開編輯區或按「儲存設定與字典」時，程式比對原本的輸出與你改過的文字，把新出現的字詞列在設定頁的「自動新增（候選）」清單。

- 按 **「加入」**：該字詞加進自動字典，之後與你手動輸入的字典一起交給 Whisper 與 LLM（手動字典排前面，合計最多 1000 字）。
- 按 **「忽略」**：該字詞之後不會再被建議。
- **「清空已自動加入」** 會清掉所有自動加入的字詞（手動字典不受影響）。
- 候選一定要你按「加入」才生效，不會自動套用。
- **只學習你在 Voice2Txt 編輯區的修改**。在其他程式（例如貼上之後的文件）改字，Voice2Txt 看不到，所以不會從那裡學習。

## 9. 疑難排解

| 狀況 | 處理方式 |
| --- | --- |
| LLM 整理後意思不對 | 對照畫面下方的「Whisper 原始轉錄」；若常發生，改用 `僅 Whisper` 或換一個 Ollama 模型 |
| 「開始錄音」按鈕是灰色 | 先到設定頁按「載入 / 下載模型」，等狀態列顯示「已就緒」 |
| 無法開啟麥克風 | 到 Windows「設定 → 隱私權與安全性 → 麥克風」允許桌面應用程式使用；或在設定頁換一支麥克風 |
| 處理速度不足，錄音已停止 | 電腦跟不上辨識速度。改用較小模型（`small`／`base`），或有 NVIDIA 顯示卡時改用 `cuda` |
| 狀態列一直出現「備援啟用：Ollama…」 | 確認 Ollama 正在執行，並在命令提示字元執行 `ollama list`，確認模型名稱與設定頁相同 |
| 雲端備援出現 `HTTP 400`／`401` | API key 錯誤或已失效，請重新貼上（Anthropic 到 console.anthropic.com 確認） |
| 雲端備援出現 `HTTP 429` | 超過用量上限或帳戶額度不足；到 Anthropic Console／OpenAI／Google AI Studio 後台確認方案與帳單。程式會暫停該服務 60 秒後再試 |
| 雲端備援出現 `HTTP 404` | 模型 ID 打錯，或你的帳號沒有該模型的使用權 |
| 選 `cuda` 後載入失敗 | 需要 NVIDIA 顯示卡及 GPU 版程式；否則改用 `cpu` |
| 中文出現簡體字 | 請使用「繁體中文」模式；中翻英的中文原文也會轉成繁體 |
| 自動貼上沒有作用 | 錄音期間不要切換視窗；部分以系統管理員身分執行的程式不接受一般程式貼上；快捷鍵還按著時貼上會等到放開 |
| 按 Right Alt 沒反應，且狀態列有 Typeless 警告 | Typeless 正在執行並攔截 Right Alt。改設其他快捷鍵（見「快捷鍵」），或關閉 Typeless |
| 按快捷鍵後其他程式的功能表被打開 | 見「快捷鍵」的「不啟動功能表」說明（盡力而為）；可改用不含單獨 Alt 的組合，例如 `Right Ctrl + F9` |
| 關閉視窗後程式還在 | 預設縮到系統匣；右鍵系統匣圖示選「結束」，或取消勾選「關閉視窗時縮到系統匣」 |
| 雙擊 exe 沒有開新視窗 | 只能有一個執行個體，已有的那個會把視窗顯示出來（可能在系統匣） |
| 其他程式的聲音被關掉，而且沒有恢復 | 多半是開啟了「語音輸入時靜音其他音訊」，而 Voice2Txt 被強制結束。到 Windows 音量混音程式把該程式取消靜音（見「語音輸入時靜音其他音訊」） |
| 隨便問沒有用到選取的文字 | 剪貼簿含圖片等非文字內容時會略過擷取（狀態列有說明）。可先清空剪貼簿再試 |
| 關閉視窗沒反應 | 程式正在處理尾段，請等它完成後再關閉 |

## 10. 已知限制

- 這是「分段近即時」，不是逐字串流；每段約延遲「停頓時間 + 辨識時間」。
- **翻譯結果請務必核對**，尤其是數字、時間、日期與否定句。測試中，Whisper 直接翻譯曾漏掉「開會」「明天」；本機 Ollama 在測試句中表現最好，但測試只有 3 句合成語音。
- 尚未完成真人長時間錄音與跨程式貼上的完整實測；快捷鍵與系統匣已用模擬按鍵與自動化腳本檢查，尚未由真人實際長時間使用驗證。
- 快捷鍵的已知限制：若某個鍵的放開事件在偵測前就遺失，該鍵會被視為仍按著，直到你再按它一次；真正遺失放開事件之後的 1.5 秒內再按同一個鍵，會被忽略一次。
- 被 Voice2Txt 隱藏的按鍵（含 Alt 組合中的非修飾鍵）若放開事件遺失，約 1.2 秒沒有重複按鍵事件就視為放開；因此「不會自動重複」的按鍵被隱藏後，也會在 1.2 秒後被視為放開。這個小問題正在修正中，尚未完成。
- 隨便問、前景 App 格式調整、選取文字擷取、互動聲音、靜音其他音訊、洞察等 2026-11-13 新增功能，目前只有模擬按鍵與自動化腳本的驗證，沒有真人長時間使用與麥克風實測。
- 前景 App 資訊只有視窗標題、程式名稱與你選取的文字；本程式不讀取其他程式的輸入欄位（沒有 UI Automation），不會從其他程式內的修改學習字典，也沒有雲端同步。
- 與 Typeless 同時執行時，`Right Alt` 會被 Typeless 攔截（見上方警告說明），請改用其他組合。
- Anthropic（Claude）備援尚未以真實 API key 驗證，沒有品質或延遲的實測數字。
- LLM 整理實測（5 段含贅詞與口誤的合成語音，只計 LLM 時間）：

  | 方式 | 通過 | 每段時間 |
  | --- | --- | --- |
  | 僅 Whisper | 0／5 | — |
  | 本機 Ollama gemma4 | 5／5 | 約 0.6 秒 |
  | OpenAI gpt-6-luna (high) | 5／5 | 約 2–3.3 秒 |
  | Gemini gemini-3.8-flash (low) | 2／2（另 3 段因帳號額度 HTTP 429 未回應） | 約 2.6 秒 |

  Gemini 的速度在同一天內變化很大（2.6 秒到超過 60 秒）；超過 30 秒會逾時並自動改用下一個方式。
- LLM 仍可能改錯意思，重要內容請對照「Whisper 原始轉錄」。

## 11. iPhone / iPad 版

iPhone / iPad 版是獨立的原生 App（iPhone 與 iPad 通用），在裝置上辨識，支援相同三種模式；結果透過複製或分享送到其他 App。目前**尚未完成編譯與實機測試**，需要 Mac 與 Xcode 才能安裝。

- **第一階段（Whisper）**：在裝置上辨識，完全離線（首次下載模型除外）。
- **第二階段（選用的雲端 LLM 整理）**：App 的「設定 → LLM 整理（選用）」可開啟，**預設關閉**；關閉時完全離線，不會有任何文字離開裝置。開啟後可設定 Anthropic（預設 `claude-sonnet-5-5`／low）、OpenAI（`gpt-6-luna`／high）、Gemini（`gemini-3.8-flash`／low），順序與桌面版相同（iOS 版沒有 Ollama）；需自備 API key（存放在 iOS 鑰匙圈），只送出 Whisper 轉錄文字，不送錄音，依用量付費。全部失敗時，中文／英文保留 Whisper 原文，中翻英改用 Whisper 直接翻譯。
- 雲端整理在 iOS 上尚未用真實 API key 驗證。安裝步驟與 iPad 注意事項見 [ios/README.md](ios/README.md)。
