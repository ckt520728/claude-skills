## 已遇到的陷阱與判斷錯誤

1. **桌面驗證不等於 iPad 驗收。** Chrome 的模型推論、合成音訊、模擬麥克風與 UA 偽裝，都無法排除 Safari、裝置記憶體、真實收音及主畫面執行的問題。先前發布與測試結果不能覆蓋使用者的失敗回報。
2. **下載完成不等於引擎 ready。** 模型檔案可能完整，但 WASM／ONNX session 初始化尚未完成或已失敗。v3 把錄音綁在 ready 上造成灰色按鈕；v4 只解開了這層介面依賴。
3. **修按鈕不等於修轉錄。** 受控測試可在手動送 ready 後自動轉錄，不代表 iPad 實際能送出 ready。下一位 agent 必須追到真實失敗階段。
4. **小模型的準確度與資源存在取捨。** 三句中文合成語料的 50 個正規化單位中，tiny 差異 8 個、base q8 3 個、small q8 2 個。small 仍把「三份／四份」辨成「三分／四分」，不能宣稱一般準確率已足夠。
5. **fp32 encoder 的假設沒有普遍成立。** base 改成 fp32 encoder 後，此語料差異反增為 4 個；已撤回。small 完整 encoder 與 q8 結果相同，故選下載較小的 q8；不能只依文件推論一定較準。
6. **合成英文太容易，未重現真人英文問題。** base/small 在四句英文正規化後 WER 為 0，只能說這四句保留內容，不能據此宣稱真人口音問題已修復。需使用者原句、辨識結果或經同意提供的音訊。
7. **中翻英仍為試驗。** tiny/base 曾出現明顯誤譯；切換引擎與模型不能取代日期、否定、數字及單位的核對。
8. **舊 PWA 快取會造成假更新。** 曾連續重新整理仍顯示舊模型選項。已加入內容雜湊資產路徑、SW 更新檢查、線上導覽優先網路與不同版本入口。仍需確認使用者看到的實際版本。
9. **不能把 URL／登入問題當作已證實根因。** `127.0.0.1` 是裝置自己，不能作跨裝置正式網址；但正式站 `/quality` 本來就是有效入口，`.html` 會 307 轉到它。先前懷疑少 `.html` 導致故障，後來被正式 HTTP 檢查排除。未登入時 401 是私人站的 gate，不是網站停機。
10. **沒有拿到真實錯誤前，不要再叫使用者反覆下載。** 下載大模型可能浪費時間，也未必解決相容性、記憶體或初始化問題。頁面、JS、Worker、WASM 都回 200，仍不能證明 Safari 能成功執行。
11. **待驗證的錄音啟動環節不能省略。** 現有程式在取得麥克風前會等待 `AudioContext.resume()`；目前回歸替身立即 resolve，未排除真實 Safari 在這個 Promise 或 `getUserMedia()` 停住的可能。這只是接手檢查點，不是已確認根因。
12. **工具與環境的失敗要分開記錄。** Windows Git schannel 曾回 SEC_E_NO_CREDENTIALS，對單次 workflow 設 `http.sslBackend=openssl` 後成功，未關閉 TLS 驗證。System.Speech 在 sandbox 的 SelectVoice 曾失敗，正常核准升權後成功。自動核准也曾因使用額度而未執行，後續正常重試才成功；不代表動作本身被判為不安全，也不得繞過審查。

## 接手後的順序

本段是**日後使用者明確恢復工作後**的建議；目前不要自行接續開發。

1. 先讀本文件、`handoffs.md` 最新項目、`STATUS.md` 及 v4 發布證據。確認子專案 Git 與正式站實際版本，保留既有草稿、快取及故障資料。
2. 取得使用者當下的 iPad/iPadOS、頁首版本、錄音後狀態與「載入診斷」。確認問題是錄音未開始、沒有有效 Blob、模型未 ready、解碼、推論，還是結果未顯示；不要假定最新失敗仍是 v3 灰色按鈕。
3. 在真正 Safari／裝置環境建立可觀察的失敗回饋。記錄 Promise 是否完成、Worker 是否存活、最後階段與實際錯誤；只取得必要診斷，不自動上傳錄音或逐字稿。
4. 使用同一段經授權的音訊，比較麥克風錄製與檔案輸入，並分離 ready 前後、Safari tab 與主畫面、線上與離線。避免一次改模型、精度、錄音編碼和部署方式而失去歸因。
5. 先寫能捕捉實際故障的測試，再做最小修正。沿用現有八項檢查與兩條 UI／真實 ASR 回歸，但不得將它們充當 iPad 驗收。
6. 若本機瀏覽器方案無法達到準確度／效能需求，重新確認原生或雲端方案的偏好、成本與資料授權。使用者目前只有 Windows，不能假設已有 Mac、Apple 簽署資源或願意傳送錄音。
